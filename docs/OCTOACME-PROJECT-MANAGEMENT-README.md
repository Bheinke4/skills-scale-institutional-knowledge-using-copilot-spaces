# OCTOACME Project Management Docs

This README collects and links all OctoAcme project management process documents and provides a concise summary of the core processes so contributors and stakeholders can quickly find the right guidance.

OctoAcme runs projects using a lightweight, iterative lifecycle: Initiation, Planning, Execution & Tracking, Release & Deployment, and Retrospective & Continuous Improvement. Initiatives start with a Project One-pager that validates the problem, defines measurable success criteria, and identifies stakeholders. Planning converts approved initiatives into a prioritized, estimated backlog with a Definition of Done and release milestones.

Day-to-day execution is organized around a visible project board (Backlog → Ready → In Progress → In Review → QA → Done) and a pull request workflow that favors small, focused PRs, linked issues, clear acceptance criteria, and automated checks. CI runs tests, linting, and security scans before review; releases are staged (patch/minor/major) with pre-release checks, smoke tests, and rollback plans. Blockers follow a tiered escalation path from team-level triage up to sponsor-level escalation when needed.

Roles and communication are explicit to reduce ambiguity and single-person dependency. Product Managers define outcomes and prioritize the backlog; Project Managers coordinate delivery, timelines, risks, and stakeholder communication; Developers build, test, and document; QA validates acceptance criteria and critical flows. Team cadence includes daily standups, weekly delivery syncs, demos at the end of sprints or milestones, and monthly stakeholder updates; retrospectives convert learnings into tracked action items that feed back into the backlog.
